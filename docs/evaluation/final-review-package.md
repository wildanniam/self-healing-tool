# Final evaluation review package — prepared, not frozen

D23 authorizes the immediate checkpoint: complete/audit the pilot, make justified engineering corrections and prepare approximately twenty executable conditions with a concrete protocol for owner review. Final collection follows that review and its own budget. See [pilot evidence](../evidence/pilot-followup-2026-09-08.md) and [decisions D20–D23](../decisions/2026-09-08-live-pilot.md).

The separate private issue [#176](https://github.com/wildanniam/koderea/issues/176) holds the case manifest, native preflight, oracle calibration and full proposed protocol. The host source, selectors, case details and raw outputs are deliberately not copied into this library. A public independent synthetic demo is not a reproduction of the private dataset.

Proposed coverage: twelve recoverable, four absent-target negatives and four normal controls across four existing workflow groups. Cases are purposefully chosen controlled conditions within one application, with declared overlap with pilot task families. Twenty is not statistical sufficiency or independent applications. Native setup/mutation/oracle checks establish fixture validity; they do not measure a healing method. An accepted selector and executed action are separate from semantic correctness.

After review, freeze source/package/model/configuration, manifest, resets, order/repetition, accounting and budget before observing final outcomes. Proposed methods: full versus ranker-only, three repeats each (120 planned method runs of twenty conditions), with separate no-healing sanity checks. Cases that fail setup remain visible as unstarted slots; provider failures after start count in method outcomes. Preserve wrong effects at event level and all revisions/reruns. Do not add cases until results look favorable; extensions need a coverage/question rationale, separate version and stopping rule.

Proposed model remains gpt-4o-mini, output 500, temperature zero, three candidate attempts, context/payload 8000/12000 characters and 30 candidates. Private protocol proposes action timeout 3000 ms, provider 15000 ms and recovery 45000 ms for review after the observed 5000 ms pilot timeout; library defaults and historical pilot config are unchanged. Package 0.0.2 changed terminal provider-failure handling; 0.0.3 also fixes the HTML caption so a provider failure is not described as abstention. Neither retunes selection or prompt. Proposed frozen package: 0.0.3; native fixture checks first used 0.0.2 and made no provider calls.

Final proposal: at most 144 requests and US$2.00 for one final batch (48 eligible full-mode slots × at most three attempts). The conservative price-assumption reservation bound is US$1.1021184 using 49024 input tokens and 500 output tokens per request at US$0.15/US$0.60 per million. This is not an account-level bill/guarantee. The prior pilot's unknown usage/reservation remains retained and needs explicit acknowledgement before a separate live batch. No additional paid request is authorized by this proposal.

Owner review covers task meaning, coverage/overlap, frozen protocol and budget. The concrete native preflight is implemented in the private host; a final collection entrypoint still needs to be implemented/verified against the approved freeze. Tasks 6.3/7.1 keep their owner-review portions pending. Practitioner benefit, license/release and paper claims have their later reviews; no participant or final-study results are claimed.
